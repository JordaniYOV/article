# Преобразования изображений: синтетические эффекты, версия 2.0

Пакет `planetary_vlm.distortion` содержит четыре отдельных преобразования и
`spoil_image` для их совместного применения. Это контролируемые синтетические
возмущения для проверки устойчивости. Их параметры по умолчанию не являются
измеренными характеристиками HiRISE/LROC или замороженными уровнями E2.

## Входы и выходы

- Изображение: NumPy-массив `(H, W)` или `(H, W, 3)`, RGB или BGR.
- Поддерживаемые типы: `uint8`, `uint16`, `float32`, `float64`. Для float
  интенсивности должны лежать в `[0, 1]`, без NaN/Inf.
- Все функции возвращают новые массивы; исходные массивы не изменяются.
  Размер и dtype изображения сохраняются.
- Shear и общая функция принимают **ровно одну** карту: `seg_mask` или
  `dem_mask`. Карта должна иметь форму `(H, W)` и быть выровнена с изображением.
- Для подготовки inference без чтения GT задайте `image_only=True` и не
  передавайте карты: обе карты в возвращаемом кортеже будут `None`.
- `seg_mask` хранит целочисленные ID классов; `dem_mask` — непрерывные высоты
  в `float32`/`float64`. DEM не является маской классов или валидности.
- Shear и общая функция возвращают `(image, dem_mask, seg_mask)`;
  отсутствующая карта остаётся `None`. Остальные функции возвращают изображение.

## Пять функций

| Функция | Параметры и поведение |
|---|---|
| `apply_synchronous_shear` | Плавный jitter строк/столбцов через `cv2.remap`. `max_shift_px` ограничивает каждую компоненту смещения в пикселях; `control_spacing_px` задаёт интервал контрольных линий; `seed` повторяет поле. Изображение и DEM интерполируются линейно, классы — по ближайшему пикселю. |
| `add_radiation_artifacts` | `num_hits`, `max_streak_length`, `strength`, `seed`. Яркие точки и штрихи толщиной 1 пиксель. Длина 1 даёт только точки. События могут пересекаться и обрезаться краем. |
| `apply_lens_flare` | `strength`, `center`, `radius`, `num_ghosts`, `seed`. Ахроматическая засветка, ореол и небольшие блики вдоль оси от источника к центру. `center` — нормированные `(x, y)`, `radius` — доля меньшей стороны. |
| `apply_hard_shadows` | `strength`, `vertices`, `num_shadows`, `seed`. Жёсткие границы многоугольников; интенсивность внутри умножается на `1-strength`. Координаты `vertices` нормированы в `[0, 1]`; иначе положение генерируется. |
| `spoil_image` | Фиксированный порядок: jitter → тени → lens flare → радиационные следы. Принимает `max_shift_px`, `control_spacing_px`, `scan_axis`, `num_hits`, `max_streak_length`, `flare_strength`, `shadow_strength`, `seed`. |

Для общей функции нулевой `max_shift_px`, нулевое число попаданий или нулевая сила
соответствующего эффекта отключают этап. Индивидуальные функции предоставляют
дополнительные параметры для явного положения и формы. `strength` находится
в `[0, 1]`.

Геометрия в версии 2.0 строится из редких случайных смещений. Кубические
кривые Эрмита соединяют контрольные значения с непрерывной первой производной.
Отдельные полосы не вырезаются и не склеиваются. Профили имеют нулевое среднее;
смещение соседних линий ограничено 0.35 пикселя, чтобы избежать складок и
перестановки строк/столбцов. Поэтому фактическая амплитуда может быть меньше
`max_shift_px`, особенно при маленьком интервале контрольных точек.

- `scan_axis="both"` (по умолчанию): горизонтальный сдвиг зависит от строки,
  вертикальный — от столбца. Это общий синтетический тест двух осей.
- `scan_axis="rows"`: обе компоненты зависят от строки, что ближе к временному
  jitter камеры с построчным сканированием, если строки соответствуют направлению
  сканирования в исходном продукте.
- `scan_axis="columns"`: обе компоненты зависят от столбца для другого
  направления сканирования.

Перепроецированная или повёрнутая плитка может не сохранять направление
сканирования сенсора; его надо устанавливать из provenance. По умолчанию
используются `max_shift_px=3.0`, `control_spacing_px=32`. Это заданные параметры
тестового поля, а не измеренная амплитуда/частота конкретного прибора. Старый
аргумент `shear_factor` версии 1.0 заменён на `max_shift_px`; его числовые значения
нельзя автоматически переносить как те же уровни тяжести.

Новые края изображения чёрные. Края сегментации получают `seg_ignore_label`
(по умолчанию 255); оценщик должен исключать этот ID. Выберите ID, который
не является классом, и сохраните его в протоколе. DEM получает `dem_nodata`
(по умолчанию NaN). Интерполяция, затрагивающая отсутствующие значения или
внешнюю область, сохраняет nodata вместо создания новых высот. Можно явно
передать конечный sentinel, например `dem_nodata=-9999.0`.

## Пример использования

Установка на новой машине: `python -m pip install -e ".[distortion]"`.
В текущем проекте Python находится в `.venv-benchmark/Scripts/python.exe`.
Пример ниже предполагает уже загруженные массивы `image`, `seg_mask`, `dem`.

```python
from planetary_vlm.distortion import (
    apply_synchronous_shear, add_radiation_artifacts,
    apply_lens_flare, apply_hard_shadows, spoil_image,
)

jitter_image, _, jitter_seg = apply_synchronous_shear(
    image, seg_mask=seg_mask, max_shift_px=3.0, control_spacing_px=32,
    scan_axis="both", seed=42,
)

# Только один вид порчи; карта разметки здесь не нужна.
noisy_image = add_radiation_artifacts(image, num_hits=30, seed=42,
                                    max_streak_length=8)
flare_image = apply_lens_flare(image, strength=0.4, center=(0.1, 0.2), seed=42)
shadow_image = apply_hard_shadows(image, strength=0.7, seed=42,
    vertices=[(0.0, 0.0), (0.4, 0.0), (0.7, 1.0), (0.0, 1.0)])

# Все четыре: изображение + сегментация.
degraded, _, transformed_seg = spoil_image(image, seg_mask=seg_mask, seed=42)

# Альтернативный вызов: изображение + DEM.
degraded, transformed_dem, _ = spoil_image(image, dem_mask=dem, seed=42)
```

## Воспроизводимость и оценка

Целочисленный `seed` повторяет результат при одинаковых параметрах и версиях
NumPy/OpenCV. По умолчанию seed равен 0; `None` означает новую случайность и
не подходит для воспроизводимого benchmark. Общая функция выделяет независимые
потоки случайности для всех четырёх эффектов. Изменение числа радиационных событий
не меняет расположение тени или бликов.

Сохраняйте `DISTORTION_VERSION`, commit проекта, NumPy/OpenCV, seed, полный
набор параметров, порядок этапов, исходный scene/group ID и condition ID.
Параметры тяжести необходимо выбрать на development split до итоговой оценки.
Комбинация всех эффектов — отдельное условие: она не заменяет оценку каждого
эффекта отдельно. Модули работают с массивами; сохранение файлов и provenance
остаётся ответственностью вызывающего pipeline.

Только геометрический jitter изменяет координаты. Связанные bbox/точки, если
они используются вместо растровой разметки, также требуют преобразования;
эти функции их не обрабатывают. Для нелинейного поля преобразование только
углов bbox не гарантирует охват всей цели: надёжнее преобразовать её растровую
маску и заново получить bbox. Обрезанные цели требуют явного правила видимости.
Маски и DEM-targets не передаются модели для обычного image-only inference.
Наложение тени или блика не меняет класс поверхности и не доказывает
проходимость. Тени здесь не вычисляются из DEM, положения Солнца и геометрии
камеры; lens flare не калиброван по оптике конкретного прибора.

Радиационный эффект моделирует яркие следы попаданий частиц, описанные в
[NASA Raw Images FAQ](https://science.nasa.gov/solar-system/multimedia/raw-images-faq/).
Реальные вибрации могут создавать переменные искажения вдоль снимка, см.
[USGS: Correcting spacecraft jitter in HiRISE images](https://www.usgs.gov/publications/correcting-spacecraft-jitter-hirise-images).
Эта реализация воспроизводит плавно меняющиеся смещения, но не измеренную
траекторию аппарата, TDI-смазывание или физическую модель конкретной камеры.
Синтетический прогон и unit tests подтверждают работу кода, а не научные
показатели моделей или реализм выбранных параметров.
